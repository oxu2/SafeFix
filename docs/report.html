3. Mathematical Formulation of Gen-Probe

The core idea of Generation-Guided Active Learning (Gen-Probe) is to use a model trained exclusively on generated images to act as a diagnostic “probe” on the original source data. This identifies the “domain gap”—the features present in real images that the generative model fails to synthesize.

Selection Mechanism:

  1. Probe Training: We train a model Mgen exclusively on the pool of generated images (e.g., 1000 generated images).
  2. Hardness Scoring (Entropy): We evaluate Mgen on the entire source training pool (e.g., train_idx_imagenet.npy consisting of 10,400 unlabeled original images). For each image xi, the probe outputs a probability distribution across C classes: P(y|xi). The score assigned to the image is its Information Entropy H(xi):
    $$ H(x_i) = - \sum_{c=1}^{C} P(y=c|x_i) \log P(y=c|x_i) $$
    • A low entropy (H → 0) means Mgen is confident; the generated images already cover these features well.
    • A high entropy means Mgen is entirely confused; these images contain features distinct from the generated domain.
  3. Data Selection: We sort all samples descending by H(xi) and select the top K images (e.g., 30% of the pool) that the probe model found most difficult.

4. Future Research Directions: Why did “Hard Mining” fail here?

The initial run of gen_probe yielded an accuracy of 0.5600, which is lower than random selection (0.5754). This is a well-known phenomenon in Active Learning literature: Hard Example Mining is extremely susceptible to outliers.

When a model is trained from scratch using only the Top-K highest entropy samples, it is essentially being trained on the most ambiguous, heavily occluded, or mislabeled images in the dataset. A model cannot build robust decision boundaries when given only edge cases.

Uncertainty-Weighted Stratified Strategy

The Uncertainty Stratified strategy aims to select the most informative samples (highest uncertainty) while strictly preserving a balanced class distribution in the selected subset.

1. Uncertainty Calculation (Entropy)

For a multi-class classification problem with C classes, let xi be an unlabeled sample and P(y = c|xi) be the predicted probability of class c by the current model. The uncertainty score for sample i is calculated using Information Entropy:
$$ U_i = -\sum_{c=1}^{C} P(y=c|x_i) \log P(y=c|x_i) $$
A higher Ui indicates that the model is less confident about the prediction.

2. Stratified Quota Allocation

Let K be the total target number of samples to select, and Nclasses be the total number of unique ground-truth (or pseudo-label) classes in the candidate pool. The budget is distributed uniformly across all classes:
$$ K_{class} = \lfloor \frac{K}{N_{classes}} \rfloor $$
Any remainder samples $K \pmod{N_{classes}}$ are distributed iteratively to the first few classes until the budget is exhausted.

3. Stratified Selection

For each individual class c: 1. Isolate the subset of samples 𝒮c that belong to class c. 2. Sort 𝒮c in descending order based on their assigned uncertainty scores Ui. 3. Select the top Kclass samples with the highest uncertainty from 𝒮c.

By combining point-wise entropy maximization with class-wise histogram equalization, this strategy avoids the common mode collapse in standard uncertainty sampling (where the model might exclusively select difficult samples from only one or two dominant/confusing classes).

Active Learning Strategy Usage Guide

Overview

I have implemented multiple Active Learning strategies for the safefix project to address the poor performance of the original Core-set method.

Available Strategies

1. CoreSetStrategy (Original Method)

python alpred.py --al_strategy coreset --al_initial_labeled 400 --al_embedding_dim 256
  • Principle: Selects samples farthest from labeled data (diversity-first)
  • Use Cases: Uniform data distribution, need to maximize coverage
  • Issues: May select outlier samples, disrupting class balance

2. StratifiedStrategy (Stratified Sampling)

python alpred.py --al_strategy stratified
  • Principle: Stratified sampling by class proportion, maintaining class balance
  • Use Cases: Imbalanced data, need representation from every class
  • Advantages: Maintains original data distribution, simple and efficient
  • Speed: Fastest (no feature extraction needed)

3. DiversityStrategy (Diversity Clustering)

python alpred.py --al_strategy diversity --al_clusters 100 --al_embedding_dim 256
  • Principle: K-means clustering followed by representative sample selection from each cluster
  • Use Cases: Data with natural clustering structure, need to cover different data patterns
  • Advantages: Balances diversity and representativeness

4. HybridStrategy (Mixed Strategy)

python alpred.py --al_strategy hybrid --al_coreset_ratio 0.3 --al_stratified_ratio 0.5 --al_embedding_dim 256
  • Principle: Combines advantages of multiple methods
    • 30% Core-set (diversity)
    • 50% Stratified (class balance)
    • 20% Random (randomness)
  • Use Cases: Complex data distributions, need comprehensive consideration
  • Advantages: Most robust, highly adaptive

5. AttributeFocusedStrategy (Attribute-Driven Sampling)

python alpred.py --al_strategy attribute --attribute_file save/attribute10.json \
  --al_attribute_focus color,background --al_attribute_rarity_power 1.5 --al_attribute_uncertainty_boost 1.0
  • Principle: Builds a score for every unlabeled sample by combining attribute rarity, metadata-level uncertainty, and optional diagnostic weights derived from logs.
  • Use Cases: Scenarios where human annotations describe attribute slices (color, background, hairstyle, etc.) and the model underperforms on specific combinations.
  • Advantages: Lightweight (no feature extraction), controllable focus on high-value slices, deterministic once metadata is fixed.

The total score Si for sample i is the sum across all attributes A of four components:
Si = ∑a ∈ A(Ri, a + Ui, a + Li, a + Pi, a)

Where: * Ri, a (Class-Conditional Rarity): $\left( \frac{1}{f_{a}(v_{i,a} | y_i) + \varepsilon} \right)^{\alpha}$. Default α = 0.01. Measures how rare an attribute value is within its predicted class. * Ui, a (Uncertainty): β if marked uncertain in JSON, else 0. If --al_attribute_use_entropy True is set, this is dynamically replaced by Information Entropy β ⋅ ( − ∑Plog P) from model inference. Default β = 1.0. * Li, a (Log Accuracy): γ ⋅ (1 − ACCa(vi, a)). Default γ = 0.0. * Pi, a (Frequency Penalty):  − λ ⋅ FreqRatio(vi, a). Default λ = 5.0. This term continuously suppresses over-sampling from heavily flooded slices.

Samples are sorted by Si (with a small injected noise term for tie breaking) and the top nselect indices are returned. When a sample exhibits multiple rare or low-accuracy attributes, the contributions accumulate, ensuring multi-attribute failures are prioritized.

Understanding the Frequency Penalty (P) and Generated Images While the formula for Pi, a computes a simple frequency ratio, it perfectly neutralizes the bias introduced by injecting artificially generated data. Specifically, the ratio is calculated over the combined candidate pool:
$$\text{FreqRatio}(v) = \frac{N_{\text{base}}(v) + N_{\text{gen}}(v)}{\sum_{v'} \big( N_{\text{base}}(v') + N_{\text{gen}}(v') \big)}$$
Where Nbase represents the counts in the original unlabeled dataset, and Ngen represents the newly injected synthetic bounding boxes (e.g., 1000 images focused purely on color:pink and texture:fabric). Because Ngen concentrates an enormous mass into a few specific attribute values (v), those specific values experience an artificially inflated FreqRatio. The  − λ ⋅ FreqRatio penalty ensures that the active learning selector does not blindly exhaust its budget on the synthetic flood, forcing it to balance the newly injected data against naturally occurring hard cases.

The 2D Synergy: R (Class-Conditional) vs. P (Global) At first glance, Rarity (R) rewarding low frequency and Penalty (P) penalizing high frequency seem contradictory. However, because R evaluates within a specific class (P(v|y)) while P evaluates across the entire global pool (FreqRatio), they form a powerful 2D filter: * High R + Low P (Class-rare, Global-rare): The most valuable “Hard Cases” (e.g., a “pink elephant”). They receive massive score boosts. * High R + High P (Class-rare, Global-common): Features that are generic globally but strange for this specific class. R and P partially offset, preventing the model from over-indexing on globally redundant background textures just because they appeared in a new class. * Low R + High P (Class-common, Global-common / Artificial Flooding): Boring redundant samples or the exact heavily-injected generated slices (e.g., 1000 synthetic pink dogs). The massive P penalty sinks their total Si score, acting as an automatic spam filter to prevent them from exhausting the selection budget.

Optionally, enable an additional Class Stratification Score (C) via --al_attribute_class_balance. After computing Si, the selector performs a greedy re-ranking that rewards classes whose current selections fall below their per-class quota. When the flag is set to a finite value w > 0, each class c keeps a running count nc and target quota t = nselect/Nclasses. The next candidate from class c receives an additive bonus Cc:
$$C_{c} = w \times \frac{t - n_c}{t}$$
which is added to its base score Si inside _soft_class_selection (see utils/active_learning.py). Classes under their quota get positive bonuses, while classes at or above the quota see the term shrink toward zero or become negative, letting pure attribute scores win. Candidates with unknown labels (e.g., synthetic-only entries) sit in a separate queue and are inserted only when their base score exceeds every class-adjusted option, so unlabeled data does not distort the balancing pass.

During iteration k of _soft_class_selection, every labeled candidate i from class c = yi uses the effective score
S̃i(k) = Si + Cc(k)
where $C_{c}^{(k)} = w \times \frac{t - n_c^{(k)}}{t}$, and nc(k) is the number of times class c has already been chosen. The algorithm picks the candidate with the largest S̃i(k) (breaking ties with the injected noise from the base ranking), appends it to the selection list, and then updates nc(k + 1) = nc(k) + 1 for that class. If the highest raw-score unlabeled item u satisfies Su > maxiS̃i(k), the iteration chooses u instead and leaves all class counts unchanged, where Su denotes the raw attribute score of the unlabeled candidate (no class bonus exists for unlabeled entries). That iteration simply appends u to selected. The loop stops once either |selected| = nselect or all class and unlabeled queues are empty; in the latter case _finalize_balanced_selection backfills the remaining slots from the global ranking. “All other class and unlabeled queues are empty” literally means every per-class list (and the unlabeled list) has been drained—no candidate remains to evaluate—so the loop has no further element to pull even if some deficits are still positive.

This deficit-based soft balancing is a contribution inspired by proportional-fair and deficit round-robin schedulers: we convert each class shortfall (t − nc) into a temporary additive bonus while preserving the metadata-driven ordering within every class, providing a controllable bridge between pure attribute scoring and hard stratification. The motivation was empirical: attribute scores alone over-pick head classes, yet strict round-robin ignores the large score spread across classes, so we needed a lightweight middle ground that can lean toward balance without throwing away the metadata signal—a criterion none of the standard AL heuristics offered out of the box.

Setting --al_attribute_class_balance inf bypasses the soft bonus and triggers _round_robin_class_selection, the literal round-robin implementation. Each class queue contributes its current best-scoring sample, then the queue moves to the back. Exhausted queues are removed, and the process repeats until either the requested budget is filled or only unlabeled/leftover samples remain (at which point the code falls back to global sorting in _finalize_balanced_selection). This guarantees per-class counts differ by at most one (subject to availability) before any remaining slots revert to global scores.

Round-robin mechanics (as implemented in _round_robin_class_selection): 1. Build per-class queues sorted by the raw attribute score + noise. 2. Walk the queues in order; on each step pop the head of the current class and append it to selected. 3. Move that class to the back of the list; if the queue is empty, drop it permanently. 4. Repeat until n_select items are collected or every class queue is empty, then rely on _finalize_balanced_selection to fill any residual slots from the global score ranking. This produces the same effect as traditional stratified sampling but preserves the attribute ranking within each class.

Example (ImageNet, sub_ratio=0.3, ten classes): the quota is t = 3, 120/10 = 312 samples per class. Running with --al_attribute_class_balance 0 let the desk class drop to 133 samples (4.3 %) because it had few high attribute scores. Re-running the same configuration with --al_attribute_class_balance 4 gave each desk candidate an early bonus of 4 × (312 − 133)/312 ≈ 2.29, so they entered the greedy loop sooner. The final desk count rose to 273 samples (8.8 %), while large classes such as backpack and purse were nudged down toward the quota. Desk growth stopped at 273 because the global budget nselect = 3, 120 was filled once the bonus had already reduced the biggest deficits; the algorithm cannot insert additional desk samples after the budget is exhausted even though ndesk < t. This illustrates how finite weights gently pull distributions toward balance without forcing perfect equality.

Weight tuning versus sub-ratio: because Cc = w × (t − nc)/t scales with the quota t = nselect/Nclasses, a fixed w becomes weaker as the sub-sampling ratio grows. To preserve roughly the same maximum bonus seen at sub_ratio = 0.3, scale w in proportion to t: wnew ≈ w0.3 × (tnew/312). For ImageNet’s ten classes this gives practical anchors: - sub_ratio = 0.7 (quota  ≈ 728): use w ≈ 9–10. - sub_ratio = 0.9 (quota  ≈ 936): use w ≈ 12.

Smaller weights still work but apply weaker nudges; larger weights push the distribution closer to stratified counts. Set inf if the run truly needs round-robin behavior.

The selector still picks the same total budget—(10, 400 × 0.3 = 3, 120) samples in this setup. Turning on --al_attribute_class_balance 4 does not add or remove items; it just changes which indices fill those 3,120 slots. _finalize_balanced_selection appends the highest remaining base scores until the list has exactly nselect entries, ensuring the class-aware re-ranking is purely a reordering step.

Workflow - Provide an attribute JSON (for example save/attribute10.json) that maps each attribute to per-sample values and optional uncertain indices. - Optionally restrict attention to a subset via --al_attribute_focus (comma-separated keys). - (Optional) Supply a diagnostic log with --al_attribute_log_path; each Rare Case entry contributes a failure weight (1 − ACC) through the parser in utils.active_learning.parse_attribute_priority_log. - Tune --al_attribute_rarity_power, --al_attribute_uncertainty_boost, and --al_attribute_log_acc_scale to balance between metadata-driven rarity, known uncertain slices, and empirical accuracy signals. - (Optional) Provide pre-counted generated samples via --al_attribute_extra_counts color:pink,texture:fabric; when counts are omitted they default to --num_added_img, and if the flag itself is omitted the selector now parses --attributes (tokens such as pinkcolor or fabrictexture) to auto-inject the same --num_added_img count for those attribute-value pairs.

Because the method operates purely on metadata, it integrates cleanly with the rest of the pipeline—no embedding extraction or model forward passes are required during selection.

  • Remaining portion automatically allocated to random sampling

Diversity Strategy Parameters

  • --al_clusters: Number of clusters (default: n_select//10)

Attribute Strategy Parameters

  • --attribute_file: Path to attribute metadata JSON (e.g., save/attribute10.json)
  • --al_attribute_focus: Optional comma-separated attribute keys to prioritize (default: all keys in metadata)
  • --al_attribute_rarity_power: Emphasis on rare attribute values (>=0, higher = stronger focus on rare slices)
  • --al_attribute_uncertainty_boost: Score bonus for samples marked as uncertain in metadata (>=0)
  • --al_attribute_use_entropy: If True, computes Information Entropy from model inference and uses it for the U term instead of static metadata flags (default: False)
  • --al_attribute_log_path: Optional path to diagnostic log providing Rare Case accuracies
  • --al_attribute_log_acc_scale: Scaling factor applied to each log-derived failure weight (default: 1.0)
  • --al_attribute_extra_counts: Inline list or JSON file describing additional counts to inject per attribute value (useful when synthetic data floods specific slices); inline entries without =count inherit --num_added_img, and when omitted entirely the code infers counts from --attributes tokens (value+attribute) using --num_added_img
  • --al_attribute_balance_strength: Multiplier controlling how strongly over-represented values are penalized (0 disables the term)
  • --al_attribute_class_balance: Stratified weight for enforcing class balance after attribute scoring (0 disables, inf enforces near-perfect round-robin per class)

6. Improved Strategies (New)

I have implemented two robust strategies to correct the weaknesses of previous methods (ignoring class balance or ignoring semantic rarity).

A. Uncertainty-Weighted Stratified Strategy (uncertainty_stratified)

python alpred.py --al_strategy uncertainty_stratified

Motivation: Standard uncertainty sampling often picks outliers from a single “hard” class, causing imbalance. Standard stratified sampling ignores sample difficulty. This strategy fuses them.

Algorithm: 1. Inference: Compute uncertainty for all unlabeled samples. * Multi-class: Entropy H(p) =  − ∑pilog pi. * Binary: Confidence gap 1 − |p − 0.5| × 2. 2. Quota Calculation: Determine strict sample quotas for each class c: kc ≈ Ntotal/C. 3. Selection: * For each class c, retrieve all samples predicted as c (or labeled as c if labels available). * Sort them by uncertainty (High to Low). * Select top kc samples.

Key Benefit: Guarantees diversity across classes (like Stratified) whilst maximizing information gain (like Uncertainty).
